Rework the verification chain: only no-comments (false-positive-proof), pest, and type-coverage fail; everything else becomes report-only; gate scripts move out of .opencode/. Both the verify gate AND the write-time opencode plugin become false-positive free by sharing one tokenizer-based implementation.

## Findings from exploration

- The chain lives in `composer.json` `verify` (lines 80-92) and calls shell gates in `.opencode/gates/` plus a config at `.opencode/no-comments.config.json`.
- There is **no config that runs pint after the agent writes**. Pint runs in exactly two places: `composer pint` and inside `composer verify`. No plugin, hook, or skill runs it on write. Since pint becomes report-only, the double-run concern resolves itself.
- The no-comments gate matches leader regexes (`//`, `#`, `/*`, `*`, `<!--`, `{{--`) on any added diff line in any file except md/vendor/etc. False-positive sources: `//` or `#` at the start of a line inside a PHP string/heredoc, `#` lines in yaml/env/shell files, `*` bullets in non-md text files.
- The opencode plugin (`.opencode/plugins/no-comments.ts`) has its own copy of the same regex logic, so it false-blocks on the same cases — e.g. an edit that adds a line starting with `//` inside a string literal gets blocked at write time.
- Files referencing the gates: `composer.json`, `AGENTS.md`, `.agents/skills/implement-loop/SKILL.md`, `.agents/skills/self-review/SKILL.md`, `.agents/skills/setup-ae-harness/templates/docs-agents/issue-tracker.md`, `docs/agents/issue-tracker.md`, `README.md`, `.opencode/plugins/no-comments.ts`.

## Changes

### 1. Move gate scripts to `scripts/gates/` (new folder, approved)

- `git mv` `.opencode/gates/{no-comments,mutation,crap,loop-log}.sh` and `.opencode/no-comments.config.json` → `scripts/gates/no-comments.config.json`. Delete `.opencode/gates/` if empty afterward (keep `no-memory.sh` in place if it is plugin-coupled; verify at move time).

### 2. Rewrite `no-comments.sh` to be false-positive-proof

- Restrict the checked pathspecs to code files: `*.php` and `*.blade.php` (via the config's `include`), keeping the existing excludes.
- Plain `.php` files: run the file's post-image through PHP's `tokenizer`, collect real `T_COMMENT` / `T_DOC_COMMENT` token line numbers, and intersect them with the added-line numbers from `git diff --unified=0`. Strings and heredocs containing `//` or `#` no longer match. Implemented as a small inline `php -r` block, same style as `crap.sh`.
- `.blade.php` files: regex on added lines for the unambiguous Blade comment opener `{{--` only.
- Update `no-comments.config.json`: drop the leader list for PHP (tokenizer decides), keep `{{--` for blade, set `include` to the code-file pathspecs.
- Keep the CLI contract: exit 0 clean / 1 comments found, `--staged --config` and worktree modes unchanged.

### 3. Make the write-time plugin false-positive free

Rewrite `.opencode/plugins/no-comments.ts` so it no longer carries its own regex copy. On `edit`/`write` it shells out to `sh scripts/gates/no-comments.sh` (worktree mode, `--config`) and blocks only on the script's exit code 1. One implementation, so anything the verify gate passes, the plugin passes too — the plugin can never false-block on string content, yaml, or any file type the tokenizer check ignores.

### 4. Rework `composer verify` in composer.json

Failing gates (chain stops on failure):
1. no-comments (staged, from `scripts/gates/no-comments.sh`)
2. pest (`vendor/bin/pest --parallel`)
3. type-coverage (`vendor/bin/pest --type-coverage --min=80`)

Report-only (wrapped `|| true`, labels say `report`): pint, deptrac, phpstan, mutation, crap, phpmetrics, audit. Their output is returned to the agent verbatim with no pass/fail judgment.

### 5. Update all prose references

- `AGENTS.md` Verification section: three failing gates; the rest are reports whose output the agent reads as raw output, not findings to enforce. Keep the "never weaken a gate" rule scoped to the three failing gates.
- `.agents/skills/implement-loop/SKILL.md`: path updates (`.opencode/gates/` → `scripts/gates/`), gate list rewritten (failing: no-comments, pest, type coverage; reports: pint, deptrac, phpstan, mutation, CRAP, phpmetrics, audit). Fix-round guidance: only failures of the three gates trigger fixes; report output is passed through, not acted on.
- `docs/agents/issue-tracker.md`, its `setup-ae-harness` template, `.agents/skills/self-review/SKILL.md`, `README.md`: update paths and gate descriptions wherever they mention `.opencode/gates` or the old eight-gate chain.

## Verification

- Manually stage a PHP file with a comment inside a string (e.g. a line starting `'// note` inside a heredoc) → gate must pass clean, and the plugin must not block the write.
- Stage a PHP file with a real `//` comment → gate must fail with the line listed.
- Stage a blade file with `{{-- x --}}` added → fails; with `{{ $x }}` → passes.
- Stage a yaml/`.env.example` change containing `#` lines → passes (out of scope for the gate).
- Run `composer verify` end to end; confirm report-only steps print output and never stop the chain, and the three failing gates still stop it.
