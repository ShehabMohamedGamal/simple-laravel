# Beads team onboarding: extend the init script and port it to PowerShell

## Goal

A beads-using repo with a big team gets one repeatable setup path. The team's maintainer runs the script once against a target repo; it configures the store (prefix, custom types), asks the maintainer for the remote origin and sets it as `sync.remote`, keeps per-machine config out of git, shares tickets through both Dolt refs and a committed JSONL mirror, and offers opt-in auto-sync git hooks. A PowerShell port gives Windows users the same flow.

## Decisions you locked in

- Sharing: Dolt refs sync (`sync.remote`, `bd dolt push/pull`) plus a committed `.beads/issues.jsonl` mirror.
- Custom types: asked interactively, default `wayfinder,spec,implementation,review`.
- The new stages fold into `scripts/init-beads-convention.sh`; no separate bash wizard file.
- Stages: prefix prompt, gitignore fix, first hydration pull, opt-in hooks, on top of the baseline.
- Hooks: `pre-push` runs `bd dolt push`; `post-merge` and `post-rewrite` run `bd dolt pull`. Opt-in after a confirm.
- Accepting the hooks also patches the installed tracker doc with an auto-sync note.
- Git-ignored: `.beads/config.yaml` only. `metadata.json`, `issues.jsonl`, `interactions.jsonl` stay tracked.
- PowerShell: a full port of the extended bash script, Windows PowerShell 5.1 compatible.
- Origin: the script asks the maintainer for the origin URL and sets it. It never pre-fills from the repo's git remotes and never transforms the value.

## Change 1: extend `scripts/init-beads-convention.sh`

Keep the existing flow, flags (`--force`, `--memory-gate`), and install steps. Add two small helpers in the script's own style: `confirm` (y/N gate) and `ask` (prompt with a default). Add flags `--origin URL` and `--types "a,b,c"` so scripted or CI runs skip the prompts.

New stage order:

1. Existing checks: bd on PATH, source layout, target dir.
2. Issue prefix: ask with default "auto-detect from the directory name". I will read `bd init --help` first to pin the exact mechanism (`--prefix` flag vs pre-set config) and fall back to auto-detect if neither exists.
3. `bd init` when the store is missing (existing behavior).
4. Custom types: replaces the hardcoded `types.custom` line with the ask-default stage; keeps the existing stickiness verification.
5. Origin: ask the maintainer "remote origin for beads sync", showing the form bd expects (for example `git+https://github.com/org/repo.git`, the form the tracker doc uses). Set the answer verbatim with `bd config set sync.remote`. Empty answer and no `--origin`: warn and continue; hydration skips, hooks still install but their runtime guard sees an empty `sync.remote`.
6. Gitignore: append `.beads/config.yaml` (idempotently, with a marker comment) to the target repo's root `.gitignore`, and confirm `.beads/issues.jsonl` is not ignored so the mirror stays tracked.
7. Hydration, confirm-gated: when the store has no issues, offer `bd dolt pull`; when the pull yields nothing and a worktree `issues.jsonl` exists, offer `bd import .beads/issues.jsonl`.
8. Hooks, confirm-gated: write POSIX sh hook files to `.git/hooks/` (`pre-push`, `post-merge`, `post-rewrite`), each with a `# managed by init-beads-convention.sh` marker and a guard that exits 0 silently when bd is missing or `sync.remote` is unset. Existing hooks without the marker are never overwritten; warn and skip unless `--force`. The prompt text states the pre-push caveat: tickets go up before code, so a failed code push leaves tickets already pushed.
9. Doc patch, only when hooks were accepted: insert a short auto-sync note into the installed target copy of `docs/agents/issue-tracker.md`, idempotent marker.
10. Closing summary: replace the stale "next: set sync.remote after adding a git origin" hint with a summary of what was set and what was skipped.

## Change 2: add `scripts/init-beads-convention.ps1` (full port)

Same flags (`-Force`, `-MemoryGate`, `-Origin`, `-Types`), same stages in the same order. The awk/sed work on `AGENTS.md` and the docs ports to PowerShell string operations; installed docs are written as UTF-8 without BOM. bd presence uses `Get-Command bd`. Hook file contents stay POSIX sh, since git runs hooks through its bundled sh on Windows too. Stage banners and confirm gates mirror the bash script. Windows PowerShell 5.1 compatible, no pwsh 7-only syntax.

## Change 3: this repo follows its own rule

Add `.beads/config.yaml` to this template repo's root `.gitignore` under the existing beads section, so the template eats its own cooking.

## Note on the wizard skill

The wizard skill's `template.sh` library targets standalone wizards. Since the stages fold into the existing installer, I borrow its UX patterns (stage banners, confirm gates, prompts with defaults, closing summary) rather than importing the library wholesale. The skill's process still applies: scope the stages, author them, verify statically, hand off with run instructions.

## Verification

- First, pin bd's real flags: `bd init --help`, `bd dolt --help`, `bd import --help`, and the docs for `sync.remote` URL schemes, then write the code against what they actually say.
- `bash -n` on the bash script; `shellcheck` if installed.
- PowerShell: check for `pwsh` on this machine; if present, parse the script with the PowerShell language parser for syntax errors; if absent, say so and verify by static trace only.
- Scratch test: create `/tmp/beads-target`, `git init`, run the bash script with `--origin` and `--types` (non-interactive path). Assert: `bd config get sync.remote` equals the `--origin` value verbatim, `bd config get types.custom` matches, `git check-ignore .beads/config.yaml` succeeds, the three hook files exist with markers, the patched doc note is present. Re-run to prove idempotency. Trace the interactive paths manually since they block on input.
- Run `composer verify` before commit per AGENTS.md. The staged shell and PowerShell files sit outside the no-comments gate (it scans only `.php` and Blade, confirmed in `scripts/feedback/no-comments.sh`), and pest and type coverage do not touch them.
- Commit after the gates pass.
